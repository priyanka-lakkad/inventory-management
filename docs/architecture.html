Factory Inventory Management System

System architecture

Three layers. The browser only ever talks to the Vue app and the API; the data files are never exposed directly.

Data flow

What happens when someone changes a filter on the dashboard, for example Period = Q3-2025 and Status = Delivered.

  1. User changes a filterThe filter bar writes to shared reactive state in useFilters.js (period, warehouse, category, status). It is a singleton, so every page sees the same values.
  2. View reactsThe active page reads the current filters and calls the matching method in api.js. The period is sent as month.
  3. Request is builtapi.js adds only the filters that aren't "all" as query parameters, for example GET /api/orders?status=Delivered&month=Q3-2025. The base URL http://localhost:8001/api is hard-coded.
  4. FastAPI routes the callCORS middleware lets the request through and the matching handler in main.py runs.
  5. Data is filtered in memoryapply_filters narrows by warehouse, category and status; filter_by_month expands quarters like Q3-2025 into months and matches on order_date. Nothing touches disk, because the lists were loaded at startup.
  6. Response is validatedPydantic response models check the shape, and FastAPI returns JSON. Summary endpoints compute totals first (inventory value, low-stock count, pending orders).
  7. UI updatesThe view stores raw results in refs, derived numbers are computed properties, and the template re-renders the tables and SVG charts.

At startup, mock_data.py reads all seven JSON files once when the backend imports it. Restarting the backend resets any in-memory changes.

Things worth knowing

Found while reading the code. I checked the first one against the running server.

Frontend calls endpoints the backend doesn't have. api.js calls /api/tasks (list, create, delete, toggle) and /api/purchase-orders, but main.py defines no such routes. Both return 404 today. A CreatePurchaseOrderRequest model exists, but no route uses it, and purchase_orders.json is empty.
Backlog.vue is not wired up. It isn't in the router or imported anywhere. Backlog data reaches the UI through the Dashboard instead.
Demo-grade settings. CORS allows all origins, the API URL is hard-coded, the current user is mocked, and all data resets when the backend restarts.
